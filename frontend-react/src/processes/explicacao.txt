🗂️ O que é a pasta processes/

A pasta processes/ normalmente é onde ficam as lógicas de negócio assíncronas do app — ou seja, os “passos” (processos) que acontecem entre a interface do usuário e o Redux.

Ela é o meio-termo entre o app e o servidor, cuidando de toda a comunicação com APIs e das ações Redux que acompanham esses fluxos.

💡 Em outras palavras:

A pasta processes/ guarda funções que definem o que o app deve fazer quando precisa buscar, criar, atualizar ou apagar algo — geralmente envolvendo chamadas à API e atualizações de estado via Redux.

⚙️ O que normalmente tem dentro dela:
Tipo de função	O que faz	Exemplo
fetchSomething	Busca dados da API e salva no Redux	fetchDocuments
createSomething	Envia dados pra API pra criar algo novo	createDocument
updateSomething	Atualiza um item existente no servidor	updateUserProfile
deleteSomething	Remove um item	removeDocument

Cada arquivo dentro de processes/ geralmente corresponde a uma parte do sistema (ex: documentsProcess.js, userProcess.js, billingProcess.js), e cada um define as ações relacionadas àquela parte.

🔄 Como ela se encaixa no fluxo Redux:

Um ciclo completo geralmente é assim:

Componente → Process (ação assíncrona) → Dispatch → Reducer → Store → Selector → Componente


Exemplo:

O usuário clica em “Carregar documentos”.

O componente chama fetchDocuments() da pasta processes.

Essa função chama a API (httpClient).

Dependendo do resultado, ela dispara uma ação Redux (DOCUMENTS_FETCH_SUCCEEDED ou FAILED).

O reducer atualiza o estado global (store).

O selector pega os dados atualizados da store e entrega pro componente renderizar.

🧠 Pra explicar pros seus amigos:

“A pasta processes guarda as funções que fazem o app conversar com o servidor. Elas controlam todo o fluxo de buscar, criar e deletar dados, disparando ações pro Redux quando começam e terminam. Basicamente, ela é o ‘cérebro’ que cuida da parte lógica das ações do app.”
